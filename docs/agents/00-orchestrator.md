# 统筹窗口

状态：进行中
最后更新：2026-10-05
职责：维持边界、已确认决策、目录所有权和模块契约。本窗口不写玩法实现。

其它窗口开工前先读本文件，再读自己的进度文件。只改自己那一份进度文件，以及本文件划给自己的独占目录。

## 已确认决策

### 架构

1. 引擎以虚幻为主。客户端负责输入、预测和表现。
2. 一局比赛的权威模拟放在虚幻专用服务器进程里。伤害、金钱、物品、拆塔、胜负只在该进程结算。客户端只提交输入。
3. 登录、组队、匹配、战绩放在虚幻进程之外的局外服务里。局外服务通过令牌和对局结果与专用服务器通信。
4. 一局比赛固定落在一个专用服务器进程上。并发靠同时运行很多局来扩展，不把同一局拆到多台机器。
5. 本对话窗口只做统筹。功能开发在其它对话窗口进行，窗口之间通过独占目录和契约降低耦合。
6. 每个窗口在 `docs/agents/` 下维护自己的进度文件，供其它窗口直接阅读。

### 对局

1. 玩法规则按传统 MOBA，镜头是第一人称。移动用 WASD，鼠标控制朝向。
2. 两队各 5 人，一张地图，一种模式。地图按上路 1 人、中路 1 人、下路 2 人、打野 1 人来设计，不强制把玩家锁在某一路。
3. 单局以大约 20 到 30 分钟为调数值，不设到点判负。
4. 没有友军伤害。
5. 第一版英雄是战士、法师、射手，作为后续英雄的模板。英雄总数不设上限。

### 普通攻击

1. 鼠标左键发起普通攻击命令。没有弹匣，出手间隔由攻速决定。松开左键不取消命令。准心附近的小角度内若有可见的可攻击目标，锁定离准心角度最近的那个，准心吸到该目标，命令存续期间出手朝向该目标。这个小角度只负责选择目标，不代替攻击距离。角度内没有可攻击目标时，这一下按键没有效果。
2. 命令存续且没有新的移动指令时：目标在攻击距离外，英雄走向目标；进入距离后按攻速连续出手。前摇期间英雄立定。
3. 近身攻击在挥击判定命中时提交伤害请求。飞行物在击中目标时提交伤害请求，生成时不提交。英雄窗口不结算伤害。
4. 前摇期间按鼠标右键，取消这一击，不提交伤害请求，攻速不计时。这一击已经出手时，挥击或飞行物保留，不再连下一击。
5. 新按下的 WASD 结束命令，改为玩家移动。走向目标途中也一样。攻速未就绪时，再次按左键也要等到下一次出手时刻。
6. 鼠标右键在命令存续的任意阶段停手，英雄立定，当前移动和普通攻击都停下。右键当时已经按住的 WASD 忽略，松开后再次按下才算新的移动指令。立定后不自动寻找目标，下一次普通攻击要再按左键并重新做准心选择。停手后朝向回到鼠标。
7. 目标死亡，或进入草丛并失去视野时，命令结束。
8. 每个英雄的攻击距离是单独配置的数值，不按职业写死在命令里。战士、法师、射手只提供初始配置，常见情况是战士较近、法师居中、射手较远。出手形式仍按模板区分：战士近身挥击，法师和射手用飞行物。三名英雄共用这一套命令，距离改变时不改命令逻辑。
9. 战斗模块尚未提供数值时，英雄窗口使用标明为占位的攻击距离和攻速。战斗模块落地后，这两项只从战斗模块按英雄读取。

### 伤害

1. 伤害有物理、魔法、真实三种。一次出手用哪一种，由这次伤害的配置决定，不按英雄职业、兵种、塔或技能写死。
2. 单位有物理伤害、魔法伤害、真实伤害、护甲和魔抗，都是可配置数值。具体数字以后再调，不在本轮锁定。
3. 物理伤害结算为 `max(1, 物理伤害 × (1 - 护甲 / (100 + 护甲)))`。
4. 魔法伤害结算为 `max(1, 魔法伤害 × (1 - 魔抗 / (100 + 魔抗)))`。
5. 真实伤害按配置的数值直接计入，不减护甲、魔抗和免伤，也不套用上面两条里最低为 1 的公式。物理和魔法不另乘免伤。
6. 不再使用攻击减护甲。英雄打外塔或内塔时，仍在本条结果上乘该塔配置的英雄伤害系数。基地不乘。商店里增加伤害的物品，加到哪一种伤害上由配置决定，不写死成物理。

### 成长与商店

1. 局内有等级。每个英雄 4 个技能，用技能点升级，大招需要更高等级。第一版技能只做命中扫描、飞行物和自身增益，不做地面画圈施法。
2. 经验来自附近的小兵死亡和英雄击杀，范围内的友军共享。
3. 金币来自补刀、击杀和自然增长。最后一击小兵才获得该小兵的金币。
4. 商店第一版只出售少量固定物品，例如鞋子、攻击、生命，不做合成树。
5. 死亡后的复活时间随对局推进变长。泉水回血，可以回城。
6. 生命、金币、复活秒数、攻速和攻击距离的具体数字以后再调，不在本轮锁定。

### 地图与视野

1. 三条兵线都有外塔和内塔，其后是基地。摧毁基地获胜。第一版没有兵营、水晶枢纽和超级兵。
2. 塔的目标按下面的规则选择。没有英雄锁定时，攻击射程内水平距离最近的敌方小兵，不攻击只是站在范围内的英雄。敌方英雄在该塔攻击范围内攻击己方英雄时，塔锁定这名英雄。同一拍有多名英雄第一次触发时，锁离塔水平距离最近的；距离相同则按这一拍请求的先后，先提交的锁定，后提交的不排队。锁定期间塔继续攻击这名英雄，小兵不插队，后来的英雄不把锁定转走。每座塔各自锁定。脱离只看三件事：水平距离超出该塔攻击范围、被锁定英雄 `IsAlive` 为假、可见性查询返回看不见。锁定不按秒过期。被打的己方英雄倒下，不因此解除锁定。解除发生在本拍更新之后，这一拍里已经提交的英雄攻击不再用来重新锁定；下一拍再按没有旧锁定的规则选择。解除后清空，走回攻击范围不恢复旧锁定。己方小兵不在附近时，英雄对塔的伤害使用配置里的降低系数，塔可以查询该系数。兵线不扣血。
3. `UDamageRequestSubsystem::Submit` 在覆盖最后一条请求之前，调用 `ULaneDamageFeedSubsystem::Push`，把这一条请求追加进本拍列表。最后一条请求仍留给占位接收方。兵线窗口只为这一处修改 `Source/MOBA/DamageRequest.cpp`，不替换该子系统，不在这里扣生命。塔在本拍更新结束后读取这份列表。
4. 小兵分近战和远程，按波次从三条路出兵。
5. 地图有打野营地。营地归兵线窗口，因为它是地图上的刷新点。
6. 第一版有草丛，没有插眼。
7. 敌方在草丛内时，只有己方提供者也在这块草丛里，或者该单位正在显形，队伍才看得见。草丛内仍看得到外面。同一草丛内的单位互相可见。从草丛中攻击，或在草丛中受到伤害时，对敌方整队短暂显形。己方单位对本队始终可见，包括站在草丛里。
8. 个人视线同时看可配置的水平视野距离、掩体和草丛。单位不挡视线。第一版全体提供者共用一个占位视野距离，不按单位种类拆开。存活的英雄、近战小兵、远程小兵、外塔、内塔和基地提供视野。野怪不提供视野，死亡单位不再提供。任一己方提供者看得见，整队就看得见。小地图隐藏队伍尚未看见的敌人，由表现窗口根据已复制的状态绘制。

### 开发策略

1. 开发阶段的专用服务器目标平台是 Windows。在编辑器中启动服务器，客户端从本机连接。安装源码版引擎和 Linux 专用服务器，留到要把对局放进容器或多台机器时再做。
2. 服务器模拟默认每秒 60 次，放在配置中，不写死在玩法规则里。英雄的网络同步密于小兵、野怪和塔。补刀手感偏慢，或服务器 CPU 被单位占满时，再由统筹窗口改这个默认值。先调整小兵的同步频率，再考虑降低模拟次数。
3. 局外产品在两个客户端能进入同一台本机服务器之前不安装。开发期用固定进局口令，令牌和对局结果仍走既定契约。需要账号、组队和匹配时，默认使用 Nakama，对局模拟仍留在虚幻专用服务器。同一台机器不够多开时，再加入 Agones 分配服务器进程。

## 工程落地顺序

英雄窗口已完成第一版和四个技能槽：客户端与专用服务器两个编译目标、普通攻击命令、战士、法师、射手三份占位配置，以及测试图 `TestGym`。技能只做命中扫描、飞行物和自身增益。升级仍不发放技能点。技能飞行物不在视野复制图里。

此后若要修改 `.uproject`、`Config/`、共享 `Build.cs` 或 `TestGym`，先写进提出方的进度文件，由统筹窗口登记后再改。兵线使用自己的地图和放在关卡里的生成器，不改 `GameDefaultMap`、`ServerDefaultMap` 和 `GlobalDefaultGameMode`。

当前顺序：

1. 兵线窗口：第一版已验收。刷兵、塔、基地、营地、草丛和胜负入口已编译。`Submit` 在覆盖最后一条请求之前调用 `Push`。单位实现 `IAttackable`。生命、金币和经验仍不在兵线结算。
2. 战斗窗口：第一版已验收。`Submit` 在 `Push` 和最后一条请求之后调用 `Resolve`，没有去掉 `Push`。生命到零时把 `IsAlive` 写成假，基地走 `NotifyDestroyed`。权威端出售鞋子、攻击、生命，购买和回血都在己方泉水占位半径内。死亡后复活计时随对局变长，到时落到己方泉水；读不到泉水则留在原地。回城读条已有，按键未接。鞋子移速只记在战斗状态，不写移动组件。野怪和塔死亡不发金币。英雄自己死亡后，普攻命令不会因此停下。物理、魔法和真实伤害已按配置结算，不再使用攻击减护甲。护甲或魔抗为 -100 时不除，改为 `max(1, 原伤害)`。
3. 同步窗口：第一版已验收。`IsVisibleTo` 转到 `UVisionWorldSubsystem`。复制图 `UVisionReplicationGraph` 已启用，看不见的英雄、兵线单位和飞行物不发给该连接。当前生命、生命上限和金币已只复制给英雄所属的连接，小兵、野怪和塔的战斗组件不复制。预测校正和同步频率留到后面。
4. 局外服务：两个客户端能进入同一台本机服务器之前不安装产品。开发期继续用固定进局口令。
5. 表现窗口：第一版已验收。小地图只画客户端上已有的英雄和兵线单位，不调用视野查询。HUD 只读本地英雄的当前生命、生命上限和金币；组件不在客户端时留空。别人的血条和金币、商店、结算、受击和开火特效没进这一刀。代码在 `Source/MOBA/Presentation/`。
6. 英雄窗口：四个技能槽已验收。数字键 1 到 4 在权威端释放，只做命中扫描、飞行物和自身增益。伤害交给现有结算。升级仍不发放技能点。技能飞行物按距离网格发送，不进视野过滤。

## 契约

契约文件放在 `docs/contracts/`，只由统筹窗口新增或修改。实现窗口可以在自己的进度文件里提议契约，不能直接改契约文件。

已登记、尚未编写的契约：

- 进局令牌：局外服务发给客户端和专用服务器，用于拒绝名单外连接。
- 伤害请求：普攻、技能、塔、小兵提交给战斗模块的统一结构。
- 对局结果：专用服务器回写给局外服务的胜负和统计。
- 单位标识：同步模块用来做相关性过滤的稳定 ID。
