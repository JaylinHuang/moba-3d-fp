# 兵线窗口

状态：第一版已验收
最后更新：2026-10-05
职责：三路刷兵、路径、防御塔、基地、打野营地、草丛体积，以及服务器上的胜负状态机。小兵、野怪和建筑由专用服务器模拟。

玩法细则以 `docs/agents/00-orchestrator.md` 为准。英雄窗口的第一版已经编译，开工条件已经满足。

## 已有工程

- 工程：仓库根目录 `MOBA.uproject`。引擎：本机虚幻 5.8.3，路径 `E:\UE_5.8`。
- 英雄验收图 `/Game/Maps/TestGym`，默认模式 `MOBAGameMode`。不要改这张图，也不要改 `Config/DefaultEngine.ini` 里的 `GameDefaultMap`、`ServerDefaultMap`、`GlobalDefaultGameMode`。
- 未烹饪时，用 `UnrealEditor.exe` 加 `-server` 打开关卡并监听 7777。单独运行 `MOBAServer.exe` 不能加载关卡。
- 可被普攻选中的单位实现 `Source/MOBA/Attackable.h` 里的 `IAttackable`（`GetTeamId`、`IsAlive`）。友军不可攻击，用队伍编号区分。
- 普攻命中后，请求进入 `UDamageRequestSubsystem`。这个子系统只记录请求，不改生命、金钱和经验。兵线不要替换它，也不要在这里扣血。
- 可见性查询是 `UHeroVisibilityQuery`，当前默认全部可见。草丛只摆放体积并记录谁站在里面。不要修改这个查询，过滤留给同步窗口。

## 独占目录

- 新建兵线代码，放在 `Source/MOBA/Lane/`。现有模块会编译该目录下的源文件，因此不要为了这些文件去改 `Build.cs`。
- 新建兵线地图，建议 `/Game/Maps/LaneTest`。生成器放在这张图里，或由只在这张图上生效的 Actor 启动。不要改 `MOBAGameMode` 的英雄测试生成逻辑。
- 兵线路点、刷兵、近战与远程小兵的移动和索敌。
- 每路外塔、内塔、基地、泉水。
- 塔的攻击优先级，以及己方小兵不在附近时对英雄伤害的降低。降低系数先做成配置，伤害数值仍交给战斗窗口结算。
- 打野营地的位置、野怪刷新和重新进入营地。
- 草丛体积，以及单位进入、离开体积的记录。
- 对局状态：对线、基地被摧毁、对局结束。基地被摧毁时在服务器上进入结束状态，并留下供局外窗口以后读取的结果。现在不写战绩存储。

若必须修改 `.uproject`、`Config/`、共享 `Build.cs` 或 `TestGym`，先把原因写进本文件的进度日志，等统筹窗口登记后再改。

## 禁止修改

- `docs/agents/` 下除本文件以外的进度文件
- `docs/contracts/`
- `Source/MOBA` 里普攻命令、角色移动、镜头、`HeroVisibilityQuery`、`CombatStatSource`
- `Source/MOBA/DamageRequest.cpp` 只允许加这一处：在 `Submit` 覆盖最后一条请求之前调用 `ULaneDamageFeedSubsystem::Push`。其余逻辑不改，不替换该子系统，不扣生命。
- `Plugins/HeroTemplates/`
- 伤害、攻速、攻击距离、金钱和经验的数值公式
- HUD、特效和小地图绘制
- 登录、匹配和服务器分配

## 依赖契约

- 伤害请求：塔、小兵和野怪造成伤害时，提交现有的 `FHeroDamageRequest`。生命结算契约尚未编写，本窗口不补这个结算。统筹窗口已允许在 `Submit` 覆盖最后一条请求之前调用 `Push`。本窗口只加这一处调用，不替换该子系统，也不在这里扣血。
- 对局结果：基地被摧毁后发出，契约尚未编写。先在服务器对局状态里留下胜负，不写入局外服务。
- 单位标识：供同步模块过滤，契约尚未编写。Actor 本身可以先充当被 `IAttackable` 选中的单位。

## 当前计划

1. 做 `/Game/Maps/LaneTest`。图里先放一条完整兵线：路点、外塔、内塔、基地、泉水，并留出另外两条路的生成位置。
2. 服务器按波次生成近战和远程小兵，小兵沿路点移动。小兵、塔、基地和野怪实现 `IAttackable`。`IsAlive` 在战斗模块写入生命之前保持为真，基地结束状态除外。
3. 摆放至少一个打野营地和一块草丛体积。营地按间隔重新生成野怪。草丛记录进出的单位。
4. 塔在没有英雄锁定时，攻击射程内水平距离最近的敌方小兵，不打只是站着的英雄。敌方英雄在该塔攻击范围内攻击己方英雄时锁定他。同一拍有多名英雄第一次触发时，锁离塔水平距离最近的；距离相同则按这一拍广播先后，先到的锁定，后到的不排队。锁定期间继续打他，小兵不插队，后来的英雄不转移。每座塔各自锁定。脱离只看三件事：水平距离超出该塔攻击范围、被锁定英雄 `IsAlive` 为假、可见性查询返回看不见。不按秒过期。受害者倒下不脱离。放开后清空再整段重判，锁定期间的攻击不保留，走回范围不恢复旧锁定。己方小兵不在附近时，英雄对塔的降低系数在配置里，并可由塔查询。本窗口不扣血。`Submit` 已在覆盖最后一条请求之前调用 `Push`，塔能在验收图上看到英雄攻击触发的锁定。
5. 提供服务器上的基地被摧毁入口。调用后对局进入结束状态。不要在兵线里直接把生命减到零。

占位尺寸和刷新秒数可以写在数据里，并在进度日志标明是占位。正式经济数值归战斗窗口。
