## Context

仓库里还没有虚幻工程。统筹窗口已确认普通攻击命令，并写明英雄窗口负责第一版工程、客户端目标、专用服务器目标、一套普攻命令，以及战士、法师、射手三名模板。战斗、兵线、同步、表现和局外都在等这个工程。

权威模拟在 Windows 专用服务器进程。开发期用编辑器启动服务器，客户端从本机连接。模拟频率放在配置里，默认每秒 60 次。攻速、攻击距离的正式数值归战斗模块；该模块未落地前使用标明占位的配置。

## Goals / Non-Goals

**Goals:**

- 生成可编译的客户端目标与专用服务器目标。
- 服务器权威地执行第一人称移动和普通攻击命令。
- 三名模板共用同一套命令，只在每英雄配置和出手形式上不同。
- 命中时提交伤害请求，不在英雄模块里改生命或金钱。

**Non-Goals:**

- 技能释放、地面指示器、兵线、塔、基地、野怪、草丛体积和胜负。
- 伤害、护甲、金钱、经验和商店结算。
- 视线、掩体、草丛过滤，以及小兵的回滚。
- 登录、匹配、进局令牌的正式校验。
- 编写或修改 `docs/contracts/`。

## Decisions

### 工程放在仓库根目录

根目录放置 `MOBA.uproject`，共享模块为 `Source/MOBA`。客户端、编辑器和专用服务器各有一个 Target。英雄内容放在插件 `HeroTemplates`。

备选是把工程放进子目录。根目录与统筹文件里的 `.uproject`、`Config/`、共享 `Build.cs` 路径一致。生成目录用忽略规则隔开，不提交 `Binaries/`、`Intermediate/`、`Saved/`、`DerivedDataCache/`。

### 一个 Pawn 加三份数据

`ACharacter` 承载移动和普攻状态机。战士、法师、射手是三份英雄数据，不是三套命令。数据包含占位攻击距离、占位攻速、占位前摇时长和出手形式。插件内用三份数据资产区分模板。后续英雄再各建独立插件。

备选是现在就拆成三个插件。三名模板的意义是证明同一命令能换距离和出手形式，先拆插件只会增加共享工程文件的改动。

### 移动使用角色移动组件

地面移动和客户端预测沿用虚幻角色移动组件。客户端发送按键与朝向，服务器校正位置。本变更不自建回滚框架；同步窗口以后替换校正策略时，普攻状态机仍以服务器为准。

### 普攻是服务器上的状态机

左键、右键和 WASD 的按下沿由客户端发给服务器。状态机只在服务器推进，并把阶段和锁定目标复制到客户端。阶段为：无命令、走向目标、前摇、出手间隔。

前摇期间英雄立定。右键在任意阶段结束命令并立定；前摇中还会取消这一击，不提交伤害请求，也不开始攻速间隔。新按下的 WASD 在任意阶段结束命令并改为玩家移动；若这一击尚未出手，这一击取消，同样不提交伤害请求、不计攻速。已经出手的挥击或飞行物保留。右键当时已经按住的 WASD 忽略，松开后再次按下才算新的移动指令。

备选是把未出手的挥击维持到判定帧才允许 WASD 移动。统筹文件写明新按下的 WASD 结束命令并改为玩家移动，走向目标途中也一样，因此前摇中的新移动键立即交还移动。

命令存续期间，视角转到锁定目标并保持在该目标上。命令结束后，朝向回到鼠标。

### 出手与伤害请求分开

战士在挥击判定命中锁定目标时提交一次伤害请求。法师和射手生成飞行物时不提交；飞行物击中锁定目标时提交一次。伤害请求只携带来源、目标和出手形式，占位接收方不修改生命。正式结构等统筹窗口写入契约后再替换。

### 可见性与可攻击目标做成查询

目标必须实现可攻击接口，并且对攻击者当前可见。友军不可攻击。选择角度是配置值，只用于挑选准心附近角度最小的目标，不代替攻击距离。角度内没有目标时，这次左键没有效果。

可见性查询默认返回可见。同步窗口落地后替换该查询，普攻命令不引用草丛体积。

### 占位数值单独存放

占位攻击距离、攻速和前摇放在英雄数据上，并带占位标记。命令逻辑不读取职业枚举来决定距离。战士初始距离小于法师，法师小于射手。具体数字不作为平衡结论，只求能在测试图里分出近、中、远。

### 测试图不是对局地图

用一张平坦的测试图启动专用服务器，并生成可攻击的对照单位。兵线地图不在本变更中制作。

## Risks / Trade-offs

- [本机没有虚幻引擎] → 实现前由使用者安装 Windows 版引擎并完成 Epic 登录与许可。工程文件里的引擎版本跟已安装版本走，不在本设计里猜一个版本号。
- [占位攻速和距离被当成正式数值] → 数据集中存放并标明占位。战斗模块落地后只从该模块按英雄读取。
- [可见性占位使草丛尚未生效] → 查询只有一个入口。同步窗口替换查询后，丢失视野仍会结束命令。
- [伤害请求字段与将来的契约不一致] → 字段保持最小，放在英雄模块内。不改 `docs/contracts/`。
- [角色移动组件的预测与日后的同步策略重复] → 普攻命中和命令结束只认服务器。客户端预测只影响移动表现。

## Migration Plan

这是第一版工程，没有旧玩法数据需要迁移。若要撤回，删除本次新增的工程文件、插件和忽略规则即可。

实现开始前，若本机找不到虚幻引擎，停止生成工程，由使用者安装引擎后重新执行。
